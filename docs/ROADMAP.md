# 从可运行原型到可验证的作品集

## 项目定位

暂定标题：Evidence First RAG — 面向证据不足问题的可追溯资料问答。
目标：在公开资料上研究检索、回答支持程度与拒答的取舍。工程改进不等同于学术新颖性；未检索相关研究、未完成实验前不宣称首创。

## 阶段 1：理解已运行的原型

运行网页与测试，从一个问题追踪 BM25、Top-k、拒答、引用的完整流程。
学习任务：解释为何 BM25 和余弦分数不能直接相加；解释检索命中与答案正确的区别；找到当前无答案漏拒答样例。
产物：可运行原型、失败案例、自己的架构说明。

## 阶段 2：建立公开且有出处的数据集

选一个范围明确的公开软件文档集合，逐项核对允许使用的方式并保留版本、URL 和许可。实现分块与稳定 chunk ID。
已完成第一版 100 题 Python 文档中文挑战集（16 块笔记、开发/测试各 50 题），包含直接问答、表达改写、跨段问题和“关键词相似但文档未提及”的无答案问题。题目由 AI 辅助编写，独立人工审核尚未完成；继续扩展和审核至 100–200 题。
将开发集与测试集按文档/主题分开，避免同一资料的近重复问题跨集合泄漏。人工核对答案及相关证据；测试集不用于调阈值。

## 阶段 3：对比基线

固定同一语料、分块、候选数、生成模型和提示词，对比 BM25、向量检索、RRF 混合，以及后续加入的交叉编码器重排序。固定模型版本与运行环境，分开测量索引构建、热查询和生成耗时。
先跑真实本地模型的小规模验证，再确定是否需要 GPU；不预先承诺硬件或下载大模型。

## 阶段 4：验证改进假设

假设 A：问题需要的关键条件若未被证据覆盖，即使检索分数很高，也应拒答。
假设 B：按回答中的事实逐条检查证据支持程度，比仅检查引用编号更能发现不受支持的回答。
假设 C：简单问题采用较少的候选资料，复杂问题才增加检索与重排序步骤，可降低平均耗时。

先实现 A，再考虑 B 和 C，避免同时改太多因素。比较无拒答、固定词项门槛、改进门槛，记录有答案误拒答与无答案漏拒答两类错误。去掉新模块做消融，确认变化来自哪里。

主要指标：Recall@k、MRR、人工核验回答正确率、引用支持率、拒答 precision/recall、回答覆盖率、P50/P95 延迟与实际 token 用量。样本足够时报告置信区间。由模型辅助评分的结果要单独标注，并抽样人工复核。

## 阶段 5：整理可以证明的个人贡献

保留实验配置、数据版本、逐题输出、失败案例和改进前后比较。制作演示与复现说明；简历只使用真正运行得到、能够复现的结果。
每次学习记录三个问题：我修改了什么？为什么这样修改？什么证据支持这个选择？

## 当前不包含

没有真实业务数据、研究数据、真实模型实验成绩或已证实的算法创新。暂无 PDF 上传、重排序器、事实级引用验证及独立人员审核的盲测集。已有按主题分开的自建开发/测试集和离线基线，见 [基线分析](BASELINE.md)。
