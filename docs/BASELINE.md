# 公开资料评测基线 v0.1

日期：2026-09-25。语料与题目版本：python-docs-zh-v0.1。配置：BM25，k=3，min_overlap=0.15；无生成模型、无 API 调用。使用当前已有参数，没有根据本次测试集调参。

## 实测结果

开发集：50 题，34 个有答案、16 个无答案。Recall@3=0.9706，MRR@3=0.9559；无答案拒答 12/16，有答案放行 31/34。

测试集：50 题，34 个有答案、16 个无答案。Recall@3=1.0000，MRR@3=0.9706；无答案拒答 3/16，有答案放行 32/34。

测试主题上的无答案漏拒答很严重，不能把高检索召回解释为系统可靠。仅有 16 道无答案题，每题改变比例 6.25 个百分点；这不是足够大的统计样本。题目由 AI 辅助编写，尚缺独立人工审核。

## 开发集失败分析

1. `list-edit-q2`：问 remove 遇到不存在的值会怎样，正确块已经找到，但 overlap=0.1，低于门槛，被误拒答。词项门槛误伤短问题。
2. `stack-q3`：问最后放进栈的元素是否先取出，Top-3 没有栈块。双字分词对表达改写不足；需要语义检索对照。
3. `list-pop-q5`：问 pop 的精确耗时，资料只介绍行为。overlap=0.1875，仍被放行。词项相似不等于包含所需数值。
4. `range-q5`：问所有解释器固定占用多少字节，资料没有这项保证，却被放行。必须检查问题限定条件是否有支持。

这些是原文摘录门槛错误，尚不能称为 GPT 幻觉率。后续生成可能拒答，也可能根据外部知识补充，必须单独测量。

## 下一次实验

先人工复核题目，再在开发集对比现有门槛与“所问属性/条件是否被证据覆盖”的判断。报告无答案漏拒答、有答案误拒答、生成引用支持程度和实际 token 用量；不能只优化一个拒答比例。

测试集本次已观察，仅作为冻结回归集。后续声称泛化改进时，应增补未见主题或由独立人员编写的新题。评测中的参考答案不传给检索器或生成模型。
